# Plotwell

Python 3.10以降、標準ライブラリのみで動く物語生成CLIです。既定の接続先は `http://127.0.0.1:9931`。OpenAI互換APIを使います。

```powershell
Copy-Item .env.example .env
python -m plotwell examples/plot.json
python -m unittest discover -s tests -v
```

環境変数は `.env` より優先し、`--endpoint`・`--model` はさらに優先します。モデル未指定ならモデル一覧の先頭を使用します。
構成・台本・演技にはJSON Schema出力、予算配分にはJSONモードが必要です。構成の空配列や編集後のターン数も制約し、形式違いによる再生成を減らします。

## 入出力

plotは [設計書](story_generation_design.md) のJSONです。charactersにはnarratorと1人以上の人物を指定してください。
title・premise・turn_budgetは省略・null可、milestonesは省略・空配列可。未指定予算はLLMが最大100で提案します。
公開plot / storyスキーマは変更していません。

既定で `data/` にUTCの `yyyymmdd-hhmmss-msZ-unique` を共通名にして出力します。unique部分は8桁の16進数です。

- `.log`: 最初に入力JSON、その後に1行1JSONで進捗を追記。入力と同一の長い設定文は `{"$input": ["characters", "人物名", "background"]}` のように冒頭の入力内の参照先で示します。API要求・応答、検証失敗、イベント割当、予算判断、原稿、演技前後、例外、工程別usageを保存します。旧形式のログも原稿の再利用が可能です。
- `.json`: 成功時だけ、公開story形式の最終結果を出力します。失敗時はログを残して終了コード1、中断時は130です。

ログには人物の背景や秘密が含まれます。APIキーは記録しません。
`llm_usage` に工程・試行別のAPI使用量、`run_complete` に呼出し回数と使用量合計を記録します。
サーバーが返すusageのキャッシュ等の扱いはサーバー実装に従います。

## 各工程の範囲とトークン消費

| 工程 | 生成対象・渡す情報 |
| --- | --- |
| 1 | 作品・章の構成だけ。scenesは空配列。全イベントを章に一度ずつ割当 |
| 2 | 対象章のシーン構成だけ。turnsは空配列。他章はsynopsisだけ。担当イベントをシーンへ割当 |
| 3 | 対象シーンの具体的な台本。担当・完了・未来イベントを区別し、過去は要約だけ参照 |
| 4 | 章間の初期予算・実分量・イベント重要性を比較して章予算を再配分。短い理由を記録 |
| 5 | 確定章予算の下でシーン間の分量と重要性を比較して再配分 |
| 6 | 対象初稿だけを確定ターン数に編集。前は要約、後は次シーン概要のみ参照 |
| 7 | 確定原稿のspeech・thoughtだけを人物ごとに演技。話者・地の文・順序・数は保持 |

milestonesは全作品の条件であり、各シーンで全件を実現する指示ではありません。
担当表の欠落・重複・順序はコードで検証します。出来事の意味の実現は生成指示に依存します。
構成の空配列もコード・制約出力で検証し、下位本文の早期生成を防ぎます。

初稿・編集の応答には、1000文字以内の継続要約、在席・観測情報、必要な新事実の簡潔な内部情報を同梱します。
要約や知識のために別のAPI呼出しを行いません。過去・後続の全台本も連結しません。
演技後の意味の検証や表現差を理由にした再生成は行いません。演技前後はログで比較できます。
形式・予算違いは指定回数内でその対象だけを再生成します。長さ制限では使用量を記録し、同じ過大入力を無条件に再送せず停止します。

## 同じ原稿からA/B比較

```powershell
python -m plotwell examples/multi_scene.json --stop-after narrator
python -m plotwell --from-narrator data/<共通名>.log --acting-mode B
python -m plotwell --from-narrator data/<共通名>.log --acting-mode A
```

確定原稿と内部情報は `.log` の `narrator_checkpoint` に保存します。再利用では工程1〜6を実行しません。
SHA-256で原稿と資料を照合し、演技は複製に対して行います。同じ `performance_source.narrator_hash` が同じ原稿を表します。
現行版はcheckpoint version 3です。version 2のログは読み込み時に整合性を検証した後、旧opening / endingを除去して再利用します。章・シーン内の台本は保持します。

Bはターン順に確定演技を引き継ぎます。Aは人物別・シーン一括で、全員が同じnarrator原稿を参照します。
Bの未来参考は直近2ターンに制限し、Aではシーン原稿を共通資料として一度だけ渡します。

## 人物の認識と知識

`characters[B].how_perceived[A]` はAから見たBです。本人はselfだけ、他者は自分の名前のキーがあればそれだけを読みます。
個別キーがない場合だけothersを使う暫定仕様です。個別値がnullでもothersは読みません。
初期の人物像より作中で後から得た事実を優先します。

backgroundはnarratorだけに渡します。他者のthoughtは演技資料から除き、自分の過去のthoughtだけを保持します。
立会い・情報取得は台本生成に同梱した内部情報に従います。人物の知識と現在・未来の脚本資料は別のキーで渡します。
未来の脚本は人物の現在の知識として扱わないよう指示します。情報抽出と人物の解釈の精度はLLMに依存します。

## 確定した実験条件と暫定仕様

| 項目 | 設計書での状態 | 現行の選択 |
| --- | --- | --- |
| 最終ターン数 | 最終許容差は未確定 | 厳密一致。未指定は最大100でLLM提案。ユーザー指定の初期実験条件 |
| 発言なし描写 | 未確定 | 1ターンに数える。暫定実装 |
| 地の文と発言の前後 | 未確定 | narrationを発言前に扱う。暫定実装 |
| 導入・結末 | 章・シーン内に統一 | 設計はsynopsis、本文はnarration。地の文だけの場合もspeaker: nullのターンとして予算に含める |
| milestones | 必須性・順序は未確定 | 全件必須・記載順。ユーザー指定 |
| A / B | 比較後に選定 | 既定B。同じ確定原稿でAも実行可。最終選定は未確定 |
| others | 優先関係が未確定 | 個別キーがない場合だけフォールバック。暫定仕様 |
| 知識取得・記憶 | 詳細未確定 | 台本と同時に内部情報を生成。直近12発言・自分の8思考を保持。暫定実装 |
| 未来の参照量 | 詳細未確定 | Bは直近2ターン、Aは同一シーン原稿。暫定実装 |

実装変更と検証の記録は [CHANGE_REPORT.md](CHANGE_REPORT.md) を参照してください。
